### F3 — Implement the strict canonical decode layer with a distinct-error taxonomy
- Milestone: M0
- Size: L
- Deps: F1, F2
- Spec: Definitions & encoding — decoder MUST reject non-canonical form (MVP-SPEC.md line 73); Tamper matrix distinct-error requirement (line 168); Milestones M0 (line 153)
- Do: Build `antseal_core::codec::decode`: a canonicality-enforcing reader over the pinned crate (or in-house per F1 contingency) that hard-errors on every rejection class of line 73: duplicate map keys; non-shortest integer encodings; non-shortest length-argument encodings; indefinite-length items (maps, arrays, strings, byte strings); map keys not in strictly-ascending bytewise encoded order (strict ascent rejects duplicates and disorder via two separate variants); floats and out-of-schema simple values; trailing bytes after the top-level item; invalid UTF-8 in tstr. Errors are a `thiserror` enum with one distinct variant per class, carrying position/context but never the byte content of secret-bearing fields. The same layer is invoked on the outer manifest, the outer bundle, the inner `body` bstr contents, and the bundle-embedded manifest bytes. Library code returns errors — no panics, no `unwrap`, on any input.
- Accept:
  - One unit test per rejection class × {outer envelope, inner body} proving the exact distinct variant is returned.
  - Duplicate-key and out-of-order-key produce two different variants.
  - Truncation sweep: every strict prefix (length 0..len−1) of a valid golden encoding returns a typed error, never panics.
  - `decode(encode(x)) == x` and `encode(decode(bytes)) == bytes` for canonical inputs.
  - Error `Display`/`Debug` output contains no field byte content (reviewed test over a secret-bearing fixture).

### F25 — A span-locating splice primitive, and the fixtures that are blocked without one

- Do: Close it one of three ways, deliberately. **(a)** Commit a third base under `testdata/tamper/format/base/` and a matching golden-vector case, so the same diff applies — costs a vector-tree addition, which Q6 retains forever and D87's per-version byte ceiling now bounds. **(b)** Add the `single binary` + `EveryKind` shape as an F13 vector case and diff against it. **(c)** State the weaker property that is actually available and assert *that*: the base is the output of a named R6 shape at a pinned seed, so pin its SHA-256 in `FIXTURES.json` beside the recipe and check it, which catches "the constructor changed" without needing a golden vector. Record which and why; (c) is the cheapest and is probably right, since the base is an input to a *recipe* rather than a committed artifact.
- Accept:
  - The every-anchor-kind base's provenance is checked by a test, not asserted in prose.
  - Whatever is chosen applies to *any* fixture base that is not one of the two committed ones, not just this one — the emitter records it uniformly, for committed and synthesized fixtures alike.
  - No committed fixture grows past the 64 KiB ceiling, and no 256 MiB/16 MiB buffer becomes a file.
- Notes: The two size-cap recipes (`bundle-oversized`, `manifest-oversized`) do not have this problem: their bases *are* the two committed, diffed ones. It is specifically the third base that is unanchored, and it is now load-bearing for two fixtures rather than one.

### F39 — Decide the row policy for the 65 unrowed `manifest-`/`bundle-` schema-shape codes
- Milestone: M0
- Size: M
- Deps: F23 (which enumerates them), F15, F25 (several need a nested byte mutation); Q: the Q7 harness + the Q8 completeness registry
- Spec: Tamper matrix — every mutation fails with a **distinct** error (MVP-SPEC.md line 168); the stable error-code contract (`docs/testing/error-code-contract.md` §§1, 3, 4)
- Discovered by: **F23** (2026-07-28). The reverse-coverage check found **83** of the 95 `bundle-`/`manifest-` codes with neither a row nor an owner. Eighteen are F22's (D10's caps plus D77's mirror-only row); the other **65** are F5's and F8's schema-shape codes, and they are unrowed for the same reason F22's are: they are proven thoroughly by the codecs' own unit-level reject-tests, which are invisible to the cross-domain distinctness sweep. They are recorded in `test_util::tamper_coverage`'s `owed` lists, each tagged with the *family* it belongs to, because the decision is almost certainly per family rather than per code: `fixed-length-field` (12 manifest + 10 bundle), `conditional-field (present iff)` (10), `closed-enum` (4), `sig-policy/algorithm` (7), `empty-container` (5), `ordered-list` (6), `tuple-arity` (3), `ciphertext-shape` (2), `required-key` (2), `cross-field consistency` (4, incl. `bundle-unit-revealed-twice` and `manifest-unit-id-mismatch`).
- Do: Decide, per family, whether one representative row plus the existing unit-level matrix is the right cost/benefit, or whether every code earns a row — and record the answer where a future contributor lands on it (a decision record, referenced from the `owed` entries). Where a family gets representative rows, land them; where it does not, the `owed` entry becomes a **named non-row** with the argument, in the pattern Q8 already uses. Two facts to weigh rather than rediscover: (a) a row's marginal value here is *cross-domain distinctness*, which for a family of near-identical length errors is largely proven by one member; (b) several codes are reachable only through a mutation inside a nested container, which needs **F25**'s span primitive, so sequencing matters.
- Accept:
  - Every one of the 65 codes ends in exactly one of two states: claimed by a row, or a named non-row with its argument. No code stays merely "owed".
  - Every added row's outcome is pairwise distinct from every existing row (`check_registry` is the proof), and every added row is `project_added` in `MATRIX.json` with a justification — MVP-SPEC.md line 168 predates all of these.
  - F23's check passes with the `owed` lists emptied of everything this task took.
- Notes: Check reachability before writing a row rather than after: a code no decode surface can emit is a *finding* about the schema (or about a defensive arm that is correctly unreachable, like `unhandled_assigned_key`), and its honest end state is a named non-row, not a fixture that cannot be built. Cheap now, permanent after Q14: an unrowed code the freeze catches is an unrowed code for ever.
